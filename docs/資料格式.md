# 資料格式

所有資料都是 vault 裡的 Markdown 筆記。**筆記本身就是唯一的資料來源**；進度、等級、徽章、每週目標都在讀取時由練習記錄推導，不另外存檔。`data.json` 只放設定。

欄位名稱用英文。下列內容以 `COURSE.md` 為準；與 SPEC.md 不一致之處記在最後一節。

---

## 1. 練習記錄

檔名：`<筆記資料夾>/練習日誌/YYYY-MM-DD-HHmm-<代號>.md`（沒有代號時用場地，例如 `2026-11-20-2130-橋下.md`）。

```yaml
---
type: practice-log
date: 2026-11-18T21:10   # 本地時間，到分鐘
place: 打擊墊            # 打擊墊｜大腿｜橋下｜鼓課｜合奏
exercise: T2             # 練習代號；即興或合奏觀察時填「即興」或留空
setting: 響1靜3          # 選填：做到哪一步、節拍器設定
bpm: 70
passed: true             # true｜false；沒有代號的記錄可留空
duration_min: 6
dropped_at: ""           # 哪裡出錯，一句話
---
（以下是自由筆記，外掛不改動）
```

規則：

- 外掛建立時只寫 frontmatter 與一行空白。之後更新只用 `processFrontMatter`，不覆寫內文。
- frontmatter 讀不懂的筆記：略過，在介面列出，不自動修、不覆寫。

## 2. 由記錄推導的結果

| 項目 | 怎麼算 |
| --- | --- |
| 進度格 | 每個練習 3 格。只計 `place` 是**打擊墊**或**大腿**、`exercise` 是該代號的記錄。依 `date` 排序，從最新一則往回數連續 `passed: true` 的則數（上限 3）；最新一則是 `false` 時為 0 |
| 過關 | 3 格填滿。過關之後即使日後沒達到，徽章不收回，進度格照實顯示 |
| 鼓上的記錄 | 同一個代號、`place` 是**橋下**或**鼓課**的記錄，另外列成「鼓上」，不影響進度格與過關 |
| 等級（期） | 必做練習尚未過關的最早一期 |
| 第 6 期重新檢查 | 進入第 6 期（第 5 期必做 C4 過關那一則的時間）之後，T2、H5a–d、D2、C4、P3 各需要一則 `passed: true` |
| 徽章 | 曾經過關的練習（29 個）；五個項目各一個「項目完成」（該項目所有練習都曾過關）。取得日期＝第三次連續達到標準那一則的日期 |
| 每週目標 | 以週一為一週的開始。`place: 大腿` 分布在至少 5 個不同日期、`打擊墊` 至少 2 則、`橋下` 至少 1 則。三項都達成記為完成一週。**沒有代號的記錄也計入** |
| 成效檢視 | 最近 8 週每週的記錄則數（全部場地、含沒有代號的記錄） |
| 降速建議 | 最新一則沒達到時，下次預設 BPM 減 10。降速後又沒達到（連續兩則 `false` 且第二則 BPM 較低），顯示「建議回到前一期的必做練習」，只是建議，不改變等級 |

## 3. 練習定義（選填，可覆寫內建預設）

`<筆記資料夾>/練習定義/<代號>.md`，frontmatter 合法時以它為準。格式在階段 3 定案；提供指令「把內建練習匯出成筆記」。

## 4. 節奏卡

可以放在 vault 任何位置（例如 `1_Knowledge`）。外掛讀取所有 `type: rhythm-card` 的筆記；**只有在你按下「設為起點／終點」時**，才寫回那一張卡片的 `videos[].segments`，其他欄位與內文都不動。「新增節奏卡」指令會在設定的「節奏卡資料夾」建立新卡。

外掛不內建任何傳統節奏的譜例或影片；內容全部由你寫。

```yaml
---
type: rhythm-card
title: Maqsum
source: "Michael Frishkopf, Arab Durub charts (2009)"   # 出處，必填。空白時顯示警告
evidence: 可查依據        # 可查依據｜轉述｜推論重建（整張卡的基本型）
tradition: 埃及、黎凡特   # 地理來源，僅作索引
structure: [4/4, 十六分格]
meter: 4/4
subdivision: 4            # 每拍幾格
groups: []                # 選填，加法拍子用，例如 [2, 2, 3]
voices:                   # 這張卡用到的音：代號 → 名稱
  D: Dum
  T: Tak
  K: Ka
pattern:                  # 基本型；每軌一行
  - track: 皮
    hits: "D.T. ..T. D... T..."
variations:               # 變形，各自標依據與出處
  - label: 加裝飾（填空八分）
    evidence: 推論重建
    source: ""
    pattern:
      - track: 皮
        hits: "D.Tk T.T. D.k. T.k."
videos:                   # 範例影片，可多部
  - url: "https://www.youtube.com/watch?v=..."
    label: 範例演奏
    segments:
      - label: 基本型
        start: 83         # 秒
        end: 101
        rate: 0.75        # 選填；目前只開外部連結，保留給日後的內嵌播放器
---
## 文化脈絡

（用在什麼場合、什麼曲式、哪些樂器。每一段結尾標依據分級，例如〔可查依據：出處〕〔轉述：出處〕〔推論重建〕。）

## 演奏說明

## 依據說明
```

鼓譜寫法：

- 一個字元是一格。`.` 是休止；大寫是重音或骨架音，小寫是輕音或裝飾音（與課程的 `Rlrl` 寫法一致）。
- 空白與 `|` 只用來分隔，方便閱讀，外掛會忽略。
- 每一軌的格數必須等於 `meter` × `subdivision`（有 `groups` 時等於 `groups` 的總和）；不符時卡片顯示警告，不畫鼓譜。
- `voices` 沒列到的字元視為錯誤並顯示警告。
- 外掛把鼓譜畫成環形（沿用 `節奏練習台.html` 的圓）與格子兩種檢視，**只顯示，不提供編輯介面**；要改就改 YAML。

依據分級有兩套，各自用在不同地方：

| 用在 | 分級 |
| --- | --- |
| 節奏卡（傳統節奏） | 可查依據｜轉述｜推論重建 |
| 課程練習（COURSE.md） | 專案文件｜研究文獻｜一般教學常識｜我的設計 |

## 5. 與 SPEC.md 的差異（已與使用者確認）

| 項目 | SPEC.md | 改成 | 原因 |
| --- | --- | --- | --- |
| 練習記錄 | 無 `setting` | 加 `setting`（選填） | T2 只在「響 1 靜 3」那一步才算過關 |
| 進度格 | 所有場地都計 | 只計打擊墊、大腿；鼓上另列 | COURSE：在打擊墊過關才搬到鼓上 |
| 沒有代號的記錄 | 未定義 | `exercise` 填「即興」或留空，計入每週目標與成效檢視，不計進度 | 橋下即興基準錄音、合奏觀察 |
| 節奏卡影片 | `youtube` 單一欄位＋頂層 `segments` | `videos` 清單，每部各有 `segments` | 可以放多部範例影片 |
| 節奏卡內容 | 無鼓譜 | 加 `meter`、`subdivision`、`groups`、`voices`、`pattern`、`variations` | 使用者要視覺化鼓譜與變形 |
| 節奏卡位置 | 只能動指定資料夾 | 可讀全 vault；只在按按鈕時寫回該卡的 `segments` | 卡片在 `1_Knowledge` |
| YouTube | 階段 0 測 A／B／C | 先只做外部連結（C），內嵌移到最後的選配階段 | Error 153 在 iOS 上不穩，簡化範圍 |
| 錄音自評 | 階段 0 測試 | 先不做，用手機內建錄音 App | 簡化範圍 |
| 降速後仍沒達到 | 未提 | 顯示「建議回到前一期的必做練習」 | COURSE 的共通規則 |
| P5、D2、C3 過關標準與 D1 名稱 | 摘要版 | 照 COURSE 原文 | 以 COURSE 為準 |
